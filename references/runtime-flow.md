# 滚动调度、共享额度与恢复

借鉴 `cc-gsb-create` 的旧环境执行方法，保留 S11 单份 main、同题单首轮和最多两次字面“继续”。不引入 A/B、评分配额或旧平台截止时间。实际默认值以 `scripts/fbrlib.py:DEFAULTS` 为准；已有 settings 显式数值优先，更新 skill 不会偷偷改用户配置。

## 命令与授权

以下命令省略 `python3 <skill>/scripts/`。`--root <根目录>` 放在子命令之前。

```bash
fbr_flow.py run --batch b1110-01
fbr_flow.py run --batch b1110-01 --execute --confirm FLOW --detach
fbr_flow.py status --batch b1110-01
fbr_flow.py recover --batch b1110-01 --execute
fbr_flow.py drain --batch b1110-01 --execute
fbr_flow.py resume --batch b1110-01 --execute --confirm FLOW --detach
```

真跑默认完成：跑题/收集/本地快照 → 录屏 → 取证 → 轨迹分析 → 当前任务 AI 验收、评分和文字复核 → 轨迹模型核查过程断言 → 闸门/本地表格。跑题、录屏、取证、评价和补证队列分别工作，一题完成即可进入下一队列，完成的结果立即进入状态。跑题并发默认 5、录屏 2、取证 2、评价 `review_parallel` 默认 5 且硬上限 5（含跨进程轨迹调用槽）；needs_task_agent 由当前任务 AI 持续处理；后三者不占跑题 key 的生成额度。表格和交付写入串行化。

GitHub 推送在独立验收和 Feedback 闸门通过、首次落表之后执行；推送后回读并再次落表核查全部必填字段。完整流水线默认主动发布，明确本地模式加 `--no-publish`；平台提交另加 `--auto-submit --confirm-submit SUBMIT`。平台单存在的任务冻结自动生产，返修需另行处理。产物尚未推送时本地仍可评价，但表格不会假报可提交。spotcheck 必须由真实审核人登记。

`pause --execute` 不发起新题，当前阶段完成后保留检查点；`drain --execute` 停止新跑题和新尝试，已经有效完成的题可继续下游。两种哨兵持久保留，只有显式 resume 清除。批次预算到顶停止继续投递；已进入录屏/测试/评价的调用仍受各自超时约束，不中途破坏文件。

## 默认预算与监控

| 项目 | 数值 / 规则 |
| --- | --- |
| 同 key 整机生成并发 | 5；按网关和实际 key 的不可逆摘要共享，跨路径/批次统一抢槽 |
| 单次执行 | 3600 秒；最近 180 秒有进展时允许一次 900 秒宽限 |
| 同题累计有效执行 | 4500 秒；所有尝试和继续共用，恢复不清零 |
| 批次绝对预算 | 25200 秒；首次启动持久化 deadline，resume/watchdog 不延期 |
| 真实停滞 | 480 秒无进展、无输出、无网关保护且无进行中工具调用 |
| 网关重试保护 | 默认 900 秒，按重试间隔动态放宽，最多 3600 秒 |
| 网关等待 | 每段最多 1800 秒；同次物理尝试累计最多 2700 秒，跨尝试总额仅在显式授权配置时限制；等待不计有效执行预算 |
| 有效尝试上限 | 模型责任含首次最多 3 次；工程故障分类另计；显式物理次数上限仍有效 |
| 自行中断续写 | 同题累计最多 2 次，仍用原会话且只输入“继续” |

心跳记录输出空闲、进展空闲、工具数、SessionID、模型与网关等待。只把系统/API 错误中的 429/5xx 等作为网关信号，项目工具日志里的 HTTP 429 不触发降档。等待期间保留存活 worker 的共享 reservation，防止它自行恢复请求后超过实际并发；退避重排未运行任务不占执行线程。镜像从 API 流生成的 `system/thinking_tokens` 正增量也算进展，收到后退出网关重试等待；零增量或无效指标不算恢复。长工具调用免于简单空闲误杀，仍受总预算约束。worker 的独立绝对截止确保调度崩溃也不无限运行；恢复时未观测的时间保守计入有效执行，不凭空认定为网关等待。

遇到一次超时/504 不立即停止容器；CLI 正在内部重试时按以上网关保护继续观察。与此不同，主会话已经输出 `is_error=false / terminal_reason=completed / stop_reason=end_turn` 的最终 result，却超过 30 秒仍不退出时，执行器先导出原始轨迹，核对单轮题面、会话和最终回答，再停止归属匹配的完成容器。保留实际进程退出码和 `run/completed-<request_id>/cleanup.json`；只有该证明及其绑定的完整流、轨迹仍有效，才把这次非零退出识别为完成后的进程清理，不再按运行失败重跑。错误 result、截断输出、会话不符、最终回答不符或缺失轨迹不适用；不伪造正常退出码，不据模型文字自述成功收口。

## 降档与恢复

同一凭据使用 `~/.codex/solo11/runtime/gateway-<摘要>/` 中的压力状态与 PID 身份槽。`FBR_RUNTIME_HOME` 可用于本地隔离验证；生产进程应使用同一 runtime 与 machine_parallel 配置。

- 并发限制/rate limit/TPM 与网关 5xx 可降一档，120 秒内同波事件去重。软错误最多降到 3；已有更低档时不抬高。确切限流可降到 1。工程退避默认 30 秒起、指数增加、最多 300 秒。
- 稳定 300 秒且有成功任务可 +1；降档期每 300 秒最多一个真实生成探针，连续 3 次成功可 +1，探针失败只清计数。探针使用任务镜像、短输入，确认 result 非错误且真实回复 OK，独立容器不挂题目代码并计入共享槽位。
- 降档满 1200 秒可冲顶，观察 300 秒；观察期再次出错退回试探前档位，下一次等 2400 秒。恢复升档受 300 秒冷却约束。
- 401/403 鉴权失败停止该凭据新轮，保留现场，检查凭据后处理；换 key 使用新指纹池。实际模型与配置不符也停止，不自动换模型。

## 锁、恢复与看门狗

批次流、任务操作、共享额度和同账号提交各有文件锁；任务锁跨线程和进程有效。运行 active 时不在宿主机对 workspace 执行 Git。运行前备份 Git 配置；接受产物前停容器冻结后台写入，再对比最终树。模型自身提交、改后还原、仅缓存/文档/日志的变动均不会误判为有效代码改动。

`run/current.json` 持久化尝试、题面/初始提交/仓库摘要、容器 ID、归属标签、worker PID 起始身份及退出回执 ID。recover 的结果：活 worker 继续等待；匹配回执可收口；有合法中断且有剩余次数可恢复字面“继续”；工程失败先完整归档再用剩余次数重跑。同名容器归属不符、worker 已死但无匹配回执、密钥泄露、预算/次数耗尽都保留现场阻塞，不能盲删或重新投题。

调度退出前若只建好容器、尚未创建派发请求，可以接续同一次起跑。恢复必须核对原调度已退出、容器归属和 ID 一致、只有初始等待进程、没有本次 exec 请求或运行输出、没有会话文件、工作区仍为干净冻结基线且尝试编号一致；任一不明仍阻塞。接续保留容器、已有尝试及预算，不伪造退出回执。接管存活 worker 时优先恢复监控，重新计入同一凭据共享槽，并核对原始派发请求、PID 身份及输出路径；沿用原 worker 和退出回执，不重新发送题面。恢复后更新心跳，保留累计预算和原始截止；未观测时间保守计入有效执行，历史重试不作为新限流事件。

默认随 flow 启动 detached 看门狗，主进程异常退出后从既有计划恢复；最多恢复 50 次。明确 blocked、completed、paused、budget 不会被看门狗自动重启。某题下游失败后按 [失败修复与复验](remediation.md) 主动修复，不以 blocked 标记代替处理。批次 Feedback gate 失败会将原错误和上一候选写入任务 AI 检查点并交给当前任务 AI 修复并逐句复核，成功后立即落表；同一错误和同一候选连续没有变化时转调度补证，保留断点后继续。只有真实外部阻塞或既有预算耗尽才暂缓，不靠无限重复同一请求或降低标准通过。

只有待当前任务 AI 验收/返修时，flow 保持在线并写 waiting.json；不会因 needs_task_agent 就结束。当前 AI 完成有效 finalize 后恢复交付阶段。机器守护不能代替 AI 写事实评价，既有绝对预算和 pause/drain 仍有效。

状态位于 `batches/<批次>/flow/`，包括 plan、process、state、waiting、stop、revives 和日志。run/current、run/budget、run/heartbeat 负责逐题现场。不要手改这些文件伪造进度、预算或授权。

## 录屏与证据

先 `fbr_record.py --doctor` 真实检查 PTY、编码器和浏览器。Web 录屏方案见 [run-rules.md](run-rules.md)。候选失败不覆盖已有合格视频；截断和必需步骤遗漏不是合格交付。环境和未知 setup 失败阻塞评价，产物失败需实证。

完整测试输出进入 `evidence/command-logs/`；缓存绑定基线、镜像 ID、架构、命令/超时及脚本摘要。轨迹、录屏或快照变化必须重新取证和独立评价。评价的低档理由需给出证据锚点，并说明为何不能再低；具体规则见 [scoring.md](scoring.md)。

本地抽检使用可 seek 的 HTTP 视频服务：

```bash
fbr_preview.py run --batch b1110-01 --detach
fbr_preview.py stop --batch b1110-01
```

默认只监听 `127.0.0.1:8899`，浏览器打开返回的 URL；优先使用内置浏览器。服务只提供交付目录，支持 Range/206、无效范围 416，控制文件放在源批次 flow 下，不污染交付清单。
