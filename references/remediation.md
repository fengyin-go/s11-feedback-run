# 失败修复与复验

适用于数据调表、独立评价、必填字段和交付闸门失败。失败是下一步工作的输入；调度应主动把可修复的问题处理好，争取当前数据真实通过全部适用闸门，不只汇报“不通过”后转走。

## 按失败来源继续处理

- **字段或调表错误**：读取 `field-audit.json`、结果表“必填字段核查”与源记录，逐项定位缺失、错误映射、无效枚举或文件路径。回到真实材料修复生成逻辑或有来源的字段修订，再重新生成表格；直接改 Excel 副本不算修好。冻结交接文件保持原样，修订记录须保留原值、新值、来源、核实过程与适用任务；没有有效修订入口时补齐入口并验证，不能因此永久搁置。
- **环境可复现等级等枚举**：先读实时平台 schema，随后核实项目的实际环境配置和启动证据，选择有证据支持的准确选项。自由文本不是选项，不可仅凭文字相似转换。读 schema 不等于提交平台；核实失败时保留待查项和具体下一步，不猜值。
- **录屏、setup 或测试材料缺失/失效**：区分环境问题与真实产物问题。恢复验收环境、按原命令重试准备或补录实际功能、补充最小定向 probe，保留失败记录，再更新 facts/card 和独立回执。原有有效材料能复用就复用；变更材料后重验受影响的下游绑定。
- **评价、来源、格式、测试描述、评分依据或查重失败**：由当前任务 AI 根据具体错误及当前证据持续修复、逐句复核，再用 `fbr_reviewer.py finalize` 验证。生成回执有效但批次 gate 失败，也必须进入回修，不能反复沿用同一候选。只有轨迹分析读取 reviewer.env；其他修复由推进任务的当前 AI 完成。
- **发布或交付缺失**：保留已通过的独立验收并立即落表。完整流水线和 finalize 默认主动处理推送、可见性、SHA 回读与材料导出，再重验必填字段；无发布授权时先完成其余可做事项，明确只剩哪项授权。用户要求暂不提交平台时始终不上传、不建单。

低分或真实功能缺陷不等于数据不能通过；应如实评价和保留产物。不得为了闸门通过改被测代码、重跑刷分、删失败轨迹、手改状态、放宽枚举或证据标准，也不得把本地提交链接冒充已发布快照。

## 环境字段的有来源修订

`fbr_fields.py` 为 `repro_level` 提供保留冻结文件的修订入口。只有完成实际环境核实并读取实时平台选项后，才在本题 `review/field-revisions.json` 登记；来源 JSON 放在本题 `evidence/field-revisions/`，不跨题引用。格式：

```json
{
  "version": 1,
  "task_sha256": "冻结 task.json 的 SHA256",
  "fields": {
    "repro_level": {
      "old_value": "task.json 中的原值",
      "value": "实时 schema 中有证据支持的准确选项",
      "reason": "实际核实了什么，为什么支持该选项",
      "verified_at": "实际核实时间",
      "schema": {"path": "evidence/field-revisions/platform.json", "sha256": "该文件 SHA256"},
      "sources": [{"path": "evidence/field-revisions/environment.json", "sha256": "该文件 SHA256"}]
    }
  }
}
```

`platform.json` 保存只读 `fbr_submit.py probe` 的结果并补上实际 `checked_at`；不得保存登录凭据或 token。环境证据记录实际命令、容器/镜像、快照、退出码、启动或页面结果及原始记录路径，不能只写结论。修订会核对冻结文件摘要、原值、来源文件摘要和 schema 选项；漂移或缺失会阻止采用。表格、字段核查和交付摘要使用同一有效值，修订及来源随白名单导出。它不修改评分、题面、会话或模型产物，也不替代事实判断；其他字段不能通过这个入口任意覆盖。

## 修复闭环与停止条件

每项失败保存原因、采取的动作、证据与复验结果。相关阶段保持“修复中/待补证”，恢复时从记录继续；通过一条立即落本地表，不等全批完成。批次 gate 的自动回修保存在 `review/gate-repair.json`，模型每次候选与独立复核仍保存在 `review/recovery/`。

相同错误和同一候选连续重复、没有新证据或修正时，停止无效模型循环，交回调度检查原始材料、环境或生成逻辑，处理后继续；这不是放弃该条。真实依赖不可达时保留检查点，待恢复后重试原请求；不因一次观察超时重启存活进程。

只有确实需要用户决定/授权、证据无法取得、外部服务持续不可用或已到既有尝试/预算上限，才最终报告具体阻塞、已经处理过什么及最小下一步。修复指令不扩展跑题尝试数或预算；完整流水线包含快照发布，显式本地模式保持不发布，平台提交仍需单独授权。继续其余可处理任务，不把整批停在单条上。
