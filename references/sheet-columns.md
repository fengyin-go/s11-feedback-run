# 结果表的列

`fbr_sheet.py --batch <批次>` 先刷新白名单交付投影，再生成 `results/<批次>/result.xlsx`，两页：

- 「结果」：前 21 列保留原飞书/Excel交付格式；SOLO2 接口映射其中 19 个输入字段，提交人/时间由平台生成。后 13 列是内部用的。
- 「进度」：批次里每道题各阶段的状态和卡在哪。
- 「必填字段核查」：逐题列出平台 18 个必填输入字段的准备状态和依据，缺失阻止交付。
- 「字段修订核对」：全部题目的操作系统、子方向、已发布产物快照、录屏与备注及来源；未通过当前验收的任务明确标示，不能当作可提交结果。

表每次都从批次源记录与交付清单重新生成。要改内容就改源文件再生成，直接改表或交付副本下次会被覆盖。运行源记录继续放在 batches；workspace 与其兄弟证据目录不搬迁。

只有 Feedback 过了闸门、并且之后正文和分数都没再动过的任务才进「结果」页。

### 字段规范化和完整性核查

操作系统 `Linux arm64` / `Linux amd64` / `Linux` / `MacOS` 映射为平台枚举 `MacOS/Linux`，原始运行环境不改写。子方向 `数据采集、爬虫与RPA` 映射为 `数据采集、爬虫与 RPA`（RPA 前一个 ASCII 空格）；未知选项不得猜测，需实时核对平台 schema。

每次生成结果表同时生成「必填字段核查」页和 `field-audit.json`，覆盖全部任务及平台 18 个必填输入字段，未验收或缺失的值不得用占位值补齐。只有备注可空；提交人和提交时间是平台自动字段，未提交为空，不参与输入必填检查。

## 数据状态

「可提交」表示这一行能交。否则列出全部问题，分号连接：

| 文字 | 怎么处理 |
| --- | --- |
| 缺〈列名〉 | 平台 18 个必填输入字段不能空；备注可空，平台自动生成的提交人/时间在未提交时留空。缺 SessionID、TurnID/PromptID、轨迹文件看收集阶段；缺产物快照看有没有推送；缺运行录屏看录屏阶段 |
| 〈列名〉的取值不在选项里：… | `task.json` 里的值和选项不是逐字一致，回出题侧修 |
| 初始环境快照不是提交链接 / 产物快照不是提交链接 | 必须是带 40 位 SHA 的 commit 地址，不是仓库首页或分支地址 |
| Harness 版本只填纯版本号 | 去掉 `(Claude Code)` 之类的后缀 |
| 轨迹里有 N 轮用户输入 | 只允许首轮题面加最多两次有记录的“继续”；次数、文本或中断记录不匹配则不能提交 |
| 产物快照还没推送 | 用户确认后跑 `fbr_snapshot.py push --execute --confirm PUBLISH` |
| 抽检被退回 | 按退回原因改正文，重新过闸门 |

## 「进度」页

每题一行：任务编号，运行、收集、提交、录屏、取证、Feedback 六个阶段的状态（✓ 完成、✗ 失败、演练、空白是没做），是否已推送，以及卡在哪（第一个失败阶段的原因，或者没进结果页的原因）。

想知道下一步该跑什么命令，用 `fbr_batch.py status --batch <批次>`，比看这页直接。

## SOLO2 接口提交

`fbr_batch.py upload --batch <批次>` 默认演练：认证、读取实时字段/账号领域/历史记录，刷新交付投影，校验字段和附件。只有用户授权后才用 `--execute --confirm SUBMIT` 上传一个主会话 JSONL 与视频并建单。账号/时间由平台生成，Excel 的「缺提交人」「缺提交时间」不阻塞 API；其他错误仍全部阻断。接口细节与恢复规则见 [platform-api.md](platform-api.md)。

`review/upload.json` 必须是已回读确认、绑定当前交付摘要和全部字段的回执，才会回填远端媒体、实际账号和时间；旧占位字符串、正文变化、附件变化都不能冒充已提交。重新演练已有提交会刷新平台质检状态；没有回读到最终质检结论时，保持平台实际状态。不会自动返修、删除或覆盖远端记录。

## 本地交付清单

`fbr_batch.py export --batch <批次>` 生成 `results/<批次>/delivery-manifest.json`。清单只收反馈阶段有效、闸门文件与当前正文和分数一致、当前证据仍能通过单题规则的任务；排除原因逐题列出。每个文件记录相对 root 路径、字节数和 SHA256。`preview`、`upload`、`fbr_sheet` 都会刷新投影，防止引用过期副本；源反馈失效后旧任务不会继续出现在当前 results 中。

白名单只有主/子会话 JSONL 和 ids、录屏与录屏元数据、facts/audit/probes、feedback/gate/对应当前正文的 spotcheck，以及生成的基础任务摘要。代码、.git、run、配置备份、钩子和作者参考解信息不进入交付层。符号链接与跨任务轨迹路径拒绝导出。平台上传仅取清单中的主会话 JSONL 与视频，并再次核对实际上传字节的 SHA256。

拟导出的有效任务必须能用权限 600、与起跑指纹一致的 key 扫描白名单原件；缺 key、换 key 或缺起跑指纹会停止整次导出，已有交付投影与原始证据保留。没有有效任务时不要求 key。

环境可复现等级只能逐字使用实时平台 `repro_level.options`。环境说明、架构、安装和启动日志保留内部证据，不作为枚举值。未知值阻止交付，禁止猜映射或改冻结交接。结果表“闸门状态”必须同时通过必填字段核查和独立验收；未推送快照、缺媒体或枚举非法均显示具体原因。
